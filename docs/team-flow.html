팀 단위 사용 플로우

한 팀이 이 프록시를 실제로 어떻게 쓰는지. 프록시라는 개념부터, 팀원 셋의 하루, 그리고 데모 촬영 컷까지.

팀 플로우 파이프라인 흐름도 대시보드 목업 라우팅 문서
01

회사에 통역 창구가 하나 생긴 셈이다. 직원이 해외에 직접 전화하지 않고 창구에 말하면, 창구가 대신 전화를 건다. 그 창구가 하는 일이 셋이다. 통역해주고 (피벗), 기밀 용어는 가려서 말하고 (마스킹), 통화료를 장부에 적는다 (로깅).

02

이 팀에 누가 있나

한국 커머스 스타트업. 개발 외주로 베트남·필리핀 개발자를 쓴다. 셋은 같은 배포 문서 SOP1과 같은 칸반 보드 Kanban-B를 보며 일한다. 쓰는 말만 다르다.

데모에서 반드시 나올 질문 · 한국어는요?

RoutingTier.TIER_BY_LANGUAGE에 매핑된 언어는 en, vi, tl 셋뿐이다. ko는 매핑에 없어서 FALLBACK인 TIER_1로 간다. 즉 지훈이 한국어로 질문하면 마스킹은 되지만 영어 피벗은 안 되고, 토큰 절감도 0이다.

한국 심사위원이라면 이걸 100% 물어본다. 답은 둘 중 하나로 미리 정해두자. (가) "ko"를 TIER_2에 추가한다 — 매핑 한 줄이라 작업량은 거의 없다. (나) 지훈은 결제자·관리자 역할로만 등장시키고 질문은 하지 않게 한다.

03

팀이 공유하는 것

"LLM을 공유한다"는 표현은 정확하지 않다. LLM은 그냥 뒤에 있는 업스트림 API다. 팀이 실제로 공유하는 건 두 가지다.

✓회사 API 키 (비용 계정)

팀원이 각자 ChatGPT를 결제하지 않는다. 회사가 키 하나로 프록시를 세우고 팀원은 그걸 통해 쓴다. 사내 Notion AI와 같은 구조다.

  • 비용이 한 곳에 모인다 → 대시보드가 성립한다
  • 모든 요청이 한 관문을 지난다 → 파이프라인을 강제할 수 있다
  • 계약 종료 시 계정만 지우면 끝난다
✓팀 용어집

SOP1, Kanban-B는 팀 전체가 쓰는 말이다. 한 명이 등록하면 팀원 전원이 혜택을 받아야 의미가 있다.

  • 지훈이 등록 → Linh·Andrea 요청에 자동 적용
  • 팀 단위여야 하는 진짜 이유가 여기다
✕공유하지 않는 것 · API 키 그 자체

키는 프록시 서버 안에만 있다. Linh과 Andrea는 키를 보지도, 받지도 않는다. 구글 로그인만 한다. SecurityConfig가 /login을 뺀 전부에 인증을 걸어놨고, AuthProvider에 google·kakao·naver가 있다. 키를 나눠주는 순간 마스킹·피벗·사용량 추적이 전부 무너지므로, 이건 설계상 양보할 수 없는 지점이다.

04

세팅 · 팀장이 딱 한 번

이 네 단계가 끝나면 팀원은 로그인만 하면 된다.

  1. 1 회사 카드로 OpenAI API 키 발급 팀 전체가 쓸 키 하나. 개인별로 발급하지 않는다.
  2. 2 프록시 서버에 키 등록 서버 환경변수로 넣는다. 이 시점 이후 키는 아무도 볼 일이 없다.
  3. 3 팀원 초대 + 모국어 지정 Member.nativeLang에 저장된다. 라우팅은 감지 결과를 쓰지만, 이 값은 재번역 대상 언어를 고정하는 안전망이 된다.
  4. 4 팀 용어집에 사내 용어 등록 SOP1, Kanban-B. 이 목록이 마스킹 대상이다. 등록하지 않은 용어는 보호되지 않는다.
05

어느 하루 · 요청 하나가 지나가는 길

팀원 입장에서는 그냥 "내 언어가 되는 ChatGPT"다. 아래 6단계는 2초 안에 지나가고 본인은 보지 못한다. 탭을 눌러 세 사람을 비교해보자. 같은 파이프라인인데 티어에 따라 켜지는 단계가 다르다.

    06

    프록시가 없었다면

    이 대비가 데모의 핵심이다. 문제를 먼저 보여주지 않으면 해결책이 안 와닿는다.

    Linh이 OpenAI에 직접 물었다면

    베트남어 원문이 그대로 나가서 토큰이 1.5배 든다. 그리고 SOP1이 "Quy trình 1" 같은 걸로 번역돼 답이 엉뚱해진다.

    지훈이 키를 나눠줬다면

    마스킹도 피벗도 못 한다. 누가 얼마 썼는지 추적이 안 되고, Andrea가 계약을 끝내고 나가도 키를 계속 쓸 수 있다.

    용어집이 개인 소유라면

    Linh이 등록한 SOP1이 Andrea에게 적용되지 않는다. 팀원 수만큼 같은 용어를 반복 등록해야 한다. 지금 Glossary가 이 상태다.

    07

    데모 촬영 컷 리스트

    총 2분 50초. 시스템 흐름부터 보여주면 감이 안 온다. 사람 셋으로 시작한다. 강조된 행이 순서를 바꾸면 안 되는 컷이다.

    # 컷 화면 길이
    1 세팅팀장 시점 지훈이 키 등록 → 팀원 둘 초대 → 용어집에 SOP1 입력 20s
    2 Linh 질문TIER_2 베트남어 입력 → 베트남어 답변. SOP1이 원형 그대로 살아있는 걸 클로즈업 25s
    3 대조화면 분할 같은 질문을 OpenAI에 직접 → SOP1 깨짐 + 토큰 1.5배. 컷 2 바로 뒤에 붙인다 25s
    4 X-ray파이프라인 컷 2의 요청이 STEP 00~06을 지나가는 애니메이션. 흐름도 그대로 40s
    5 AndreaTIER_3 타갈로그. 형태소 힌트 단계가 하나 더 켜지는 걸 보여준다 20s
    6 SKIP오버엔지니어링 방어 "cảm ơn" 같은 짧은 말 → 파이프라인 통째로 우회. 임계치 50의 실측 근거 언급 15s
    7 대시보드팀장 시점 언어별 격차가 평평해진 그래프. 절감 금액이 아니라 절감률이 주인공. 목업 30s
    내레이션 한 줄 요약 회사가 프록시에 API 키를 한 번 꽂아두면, 팀원은 로그인만 하고 자기 언어로 묻는다. 프록시가 대신 영어로 물어보고 대신 답을 번역해온다. 사내 용어는 가려서 나가고 돌아올 때 복원된다.

    절감은 부제고, 주제는 "언어가 달라도 같은 AI를 쓴다"다.
    등장인물과 회사는 시연용 설정이다. 티어 규칙·임계치·언어 매핑은 routing.md의 실제 구현을 따랐다.
