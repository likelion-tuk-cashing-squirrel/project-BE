프록시 파이프라인 흐름도

프롬프트가 들어와서 응답이 나가기까지, 요청이 실제로 거치는 5단계 + 언어 티어 분기.

STEP 00 · INPUT
클라이언트 요청 수신
팀원이 자기 언어로 요청 입력 → 프록시 서버가 요청 수신
↓
STEP 01 · ROUTER
언어 감지 & 티어 분류
langdetect로 언어 판별 → TIER 2(비용 문제) / TIER 3(비용+이해력 문제) 분기
↓
STEP 02 · MASKING
용어집 마스킹
팀 네임스페이스 용어집 조회 → 고유명사·전문용어를 {TERM_01} 형태로 치환 (FlashText)
↓
TIER 2
STEP 03-A
바로 영어 피벗
형태소 처리 없이 곧장 영어로 변환
형태소 분석 skip
TIER 3
STEP 03-B
형태소 힌트 주입 후 피벗
tagalog-stemmer로 어근+접사 분해 → 힌트 포함해 영어로 변환
└──────────────┬──────────────┘
↓
STEP 04 · LLM
영어로 추론 + 답변 생성
OpenAI API 1회 호출 (번역+답변 통합 프롬프트, 비용/속도 최적 구간)
↓
STEP 05 · OUTPUT
원어 재번역 + 마스킹 복원
LibreTranslate(오픈소스)로 원어 재번역 → {TERM_01}을 원래 용어로 복원
↓
STEP 06 · RESPONSE
클라이언트 응답 + 대시보드 로깅
최종 답변 전송, 동시에 토큰/비용/속도 실시간 대시보드에 기록

예시 · 필리핀어 문장 하나가 지나가는 경로 (TIER 3)

IN→ "Nagsulat ako ng SOP1 para sa deployment"
01→ 언어 감지 → TIER 3
02→ "SOP1" → {TERM_01}로 마스킹
03-B→ nagsulat = 어근 sulat + 접두사 nag → 힌트 포함 영어 변환
04→ "I wrote {TERM_01} for the deployment" 기반으로 답변 생성
05→ 영어 답변 → 필리핀어 재번역 → {TERM_01} → "SOP1" 복원
OUT→ 필리핀어로 정확한 최종 답변 반환
